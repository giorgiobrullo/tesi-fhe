# Conditional final default verification

This supplement is fixed while the six confirmation runs are still in progress,
before their statistical analysis and before any final default copy exists.
It does not change CONFIRMATION_FREEZE.json or the candidate selection criteria.

If a candidate qualifies under PROTOCOL.md, create a separate local runtime from
the untouched September 18 version and retain only the selected implementation.
Remove the new research flags, counters and unused alternative from that copy.
Preserve meaningful differential tests and the anchor fallback when applicable.
Refresh the source/circuit/client bindings and run core and service unit tests.
Keep all previous sources, binaries, runs and publication artifacts intact.

Compare the final default with untouched stock in a new paired executable, with
the same 22 gate fixtures and six timing fixtures as the frozen confirmation.
Freeze the cleaned source, executable, fixture plan and analysis before generating
one entirely new bridge key family. Require all gate outputs and complete output
words to match, then run six warmup and 36 measured pairs in the original balanced
schedule. All five primary scenes remain primary and fallback stays secondary.
The final bridge must have primary geometric ratio below one, with no pooled
scene ratio above 1.02. Report its full confidence interval without presenting
this one-family bridge as independent proof of the earlier two-family effect.
If correctness or this bridge fails, preserve the candidate without promotion.

Also verify the final service wire/CLI with its own freshly generated compatible
keys on acceptance, rejection and winner-specific threshold fixtures. Record
the exact tested binary and generated binding hashes. Service checks are not
latency measurements and do not qualify a general noise failure bound.

Only after those checks can the new default be called a verified local baseline.
The affine component alone cannot qualify: full-query integration and validation
are separate work. No commit, push, merge, external message or publication follows.
